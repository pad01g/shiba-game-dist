# shiba-game-dist

「しばいぬのおつかい」の **OTA パッチ (`.pck`)** の配信先。GitHub Pages で配ります。
中身は CI (`shiba-game` の `ota-deploy` ワークフロー) が自動で作ります。
**手で置かないでください。**

## 置かれるもの

| | |
|---|---|
| `version_info-<x.y>.json` | 端末が最初に読む索引。版・ファイル名・sha256 |
| `patch-<x.y.z>.pck` | パッチ本体 |
| `patch-<x.y.z>.pck.sig` | その署名 |

## 端末が何をするか

1. 起動時、`user://` に検証済みのパッチがあれば `load_resource_pack()` で当てる
2. main シーンを開く (**ここで初めて上書き後のコードが効く**)
3. 裏で `version_info-<x.y>.json` を読み、新しければ落として検証し、
   **次回の起動から**使う

起動中に差し替えると、読み込み済みのシーンと新しいコードが混ざって壊れます。
だから適用は必ず次回起動からです。

## 署名

**RSASSA-PKCS1-v1_5 over SHA-256。** 公開鍵はアプリに焼き込んであり
(`assets/ota/public-key.pem`)、秘密鍵は CI Secret です。

既存 5 アプリは Ed25519 ですが、このアプリだけ RSA です。
**Godot が Ed25519 を持たない**ためで、GDScript で自前実装すると
遅すぎて危ないという判断です。理由は `shiba-game` の
`src/infrastructure/ota/bundle_verifier.gd` の冒頭に書いてあります。

**検証に落ちたパッチは端末に保存しません。** 残すと次の起動で同じ失敗を
繰り返すためです。

## x.y が一致するものだけ

`z` を上げた配信は OTA で届きます。`x.y` を上げた場合は APK の配り直し
(F-Droid 経由) が要ります。エンジンの版を上げた、ネイティブ拡張を足した、
APK 同梱のアセットを変えた、といった場合です。
